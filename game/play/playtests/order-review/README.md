# Reviews of action order

Twenty separate level reviewers played through the public Markdown interface. Each tried at least three distinct orders within its assigned level, then returned to inspect the history-aware explanations and exercise further variations. Their reports preserve sequences, outcomes, quotes, limitations, and temporary checkpoint paths. The initial saves were generated at level entrances; reviewers did not use the automatic solve fixture or read hidden state.

The follow-up pass uses the same per-action reasoning and section order as React. Each action has one numbered control immediately after its explanation. Browser source text, reference metadata, and worker progress remain visible separately; they do not duplicate the executable controls.

Some initial reports called intentional scorer exploits or direct-open failures bugs. Their rechecks and this index distinguish those mechanics from contradictory explanations. A well-formed builder request can still fail admission; discovering a working chain remains part of the game.

This is bounded playtesting. The longer coordination levels were tested through selected sequences and partial progress; the separate automated acceptance route verifies all twenty evaluations end to end. Neither procedure enumerates all arbitrary URLs, read keys, timer values, or possible action orders. Reports retain historical observations even when a later fix changes the current dialogue.
