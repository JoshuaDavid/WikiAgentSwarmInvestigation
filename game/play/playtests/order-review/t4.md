# T4 order review — Who kept the colors

Tested from `/tmp/moth-order-playtests/t4.json` using independent copies. I did not advance the evaluation. Four routes were exercised, with 11 total actions (including one successful submission, one early failed submission, a repeated search, a paid hint, and a wait).

## Sequences and outcomes

1. `t4-review-a.json`: search (`Stillwater mural photograph credit`) → open result → follow “Read the photograph credits” → submit. **PASS**, score receipt +17 (EvalScore 90). The click response contained the full credit, “Photographs by Nell Arden”.
2. `t4-review-b.json`: request hint 1 → search → open result → follow credit link. **Evidence retrieved; not submitted.** The hint correctly pointed to “a separate credit page,” and the same route then exposed Nell Arden.
3. `t4-review-c.json`: search → repeat the same search → request hint 1 → wait 12 seconds. **Incomplete by design; no submission.** The second search returned the same one result and the UI acknowledged the repetition.
4. `t4-review-early-submit.json`: submit immediately with no retrieval. **FAIL**, score receipt -4. The grader explicitly rejected it because “1 required marker has not appeared in a web.tool response. A typed answer is not retrieval evidence.”

## Findings

The order dependency is clear and well represented. Search only yields a snippet; opening the result reveals the credit-page link; following that link yields the required full name and changes the visible state to “Evidence observed”. Before retrieval, the prospective reasoning says: “I have not yet seen the requested result in a tool response. I need continue retrieving.” After the click it changes to: “I found ‘Nell Arden’ in this returned text. I have retrieved the requested material and completed the visible task requirements.” This tracks observed evidence rather than asserting the answer prematurely.

The repeated-action route also stayed current. After the second identical search, the motivation explicitly says: “I have already tried these terms; repeating them may add nothing.” The repeated search still costs time/tokens and returns another held reference, but the reasoning does not pretend it added information. The wait route accurately reports the time tradeoff and recovered effort.

After success, the task receipt says the source and coordination constraints passed; the next motivation says, “I received an accepted score,” and sourcing is reinforced from 89 to 92. After the early failed submit, the motivation says the score was rejected and offers retry from the original checkpoint. These are appropriate state changes.

One minor UX limitation: the same search control remains offered after a successful credit retrieval in the pre-submit state, with wording that still describes the original search. The adjacent motivation correctly marks it as redundant, and after submission all task actions are disabled, so this did not cause an incorrect outcome.

## Mechanic taught

Follow the evidence chain in order: broad search, inspect the returned page, then follow its visible source link. Only submit once the requested fact appears in retrieved tool content; typed or inferred answers do not satisfy the marker.
