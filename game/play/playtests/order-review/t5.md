## Findings

The task controls and prospective reasoning update correctly after open and reject a premature submission. Search results are intentionally empty, and query echoes are explicitly distinguished from source evidence.

One presentation inconsistency is reproducible after search-first actions. Preceding actions: from the initial save, search `Stillwater accession 88 ASH-GLASS` (pick 1). The task banner says `0 / 1 required markers observed in tool responses`, and the reasoning says the marker is only a query echo; however, the footer says `Moth / current instance · 0 written · 1 markers observed`. After the second empty search the same footer remains while the task banner remains at zero. This does not affect grading—the later direct open and submit pass—but the two counts can confuse readers about whether search already observed the required marker.

Coverage is deliberately bounded to these three orders and fourteen executed actions across attempts; I did not test level advancement, unavailable controls, or context compaction.
