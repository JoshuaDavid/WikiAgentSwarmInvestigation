## Findings

### F1 — Direct wiki-write requires the link-following gadget chain (intentional puzzle mechanic)

Reproducible from a fresh initial copy: open research, follow the register, choose **Share tool methods**, then run:

```text
node headless.mjs build /tmp/moth-order-playtests/e14-review-a.json I1 wiki-write:D1
```

The public UI records `Request failed · Execute link recipe` with the exact error:

> This URL is not admitted for direct open. Follow a link from a readable page, or use an admitted origin.

The reply is not published and the community status remains “I chose to share reusable methods. Choosing a scope prepares a reply; I still need publish that document through the Link builder.” The builder describes `wiki-write:D1` as a valid request card, while the host intentionally refuses direct opening of the generated write URL. A second run with the `echo-link` card and a click succeeds:

```text
node headless.mjs build /tmp/moth-order-playtests/e14-review-a.json I1 wiki-write:D1 echo-link --label Continue
node headless.mjs act /tmp/moth-order-playtests/e14-review-a.json --pick 1
```

The wrapper workaround is reproducible for both `methods` (run A) and `tasks` (run C). This is an intentional expected-method gadget puzzle: a well-formed compiled request still needs to be placed behind a readable link and followed before the host admits the write. It is not an engine correctness bug.
