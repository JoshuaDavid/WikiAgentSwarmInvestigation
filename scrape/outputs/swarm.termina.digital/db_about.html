about

an incident database for agent swarms, built the way aviation builds theirs: one row per occurrence, every fact with a source, every claim with a status, and the raw records kept so the reading can be redone.

shape

an incident is what happened at a place. a campaign is a population of agents, whatever it did and wherever it went; its kind says whether it is a swarm, one operator's run, a research environment leaking, or the visitors who came after the news. a cluster is a task inside a campaign. a venue is a place agents wrote to. a record is one observed thing at a venue: a revision, a recent-changes row, a paste, a deletion. a claim is an assertion by anyone, us included, with a status. evidence is where a claim or link comes from. a tracker is a group holding data.

download

the whole database as jsonl, one file per table, with a manifest of row counts and sha256 hashes and a json schema derived from the sqlite ddl: manifest.json, schema.json. schema version 8. the same tables as one sqlite file: incidents.sqlite. curated bundles (paste bodies, anonymised recent-changes records) with their own manifest: datasets/manifest.json. the json api is described at api.

licence

the database is dedicated to the public domain under cc0 1.0: the tables, the api, the site text, the codebook, the claims and findings. take it, quote it, rebuild it, no attribution required, though a link back helps others check the source. the full text is the LICENSE file in the repository.

cc0 covers what we wrote and measured. it doesn't change the terms of what we cite or hold from others: the collusion.wiki export and report, shellac's reading pack, swarm's sub-swarm taxonomy (cc by 4.0), the incident wiki (cc0), the recreated wiki and paste bodies, which belong to whoever wrote them, and the press and vendor reports linked from the evidence register. each evidence row names its publisher. the anonymisation of people's names and addresses is a policy, not a licence term, and it stays whatever you do with the data.

what we hold

we pull each venue's public listing whole: a wiki's recent changes for the last 180 days, a pastebin's recent or archive list, a capped number of paste bodies per run. the pull doesn't decide what an agent is; that happens at build. we keep the venue's own editors' rows locally because the scanner's thresholds are calibrated against them: humans are the control. every fetched text passes a content screen before it is written to disk, whoever wrote it.

we publish less than we hold. the wikis' own editors appear as human-n with their text withheld. paste and shortlink rows from before 2025-12 are dropped before the database is built. handles that look like personal names are masked. addresses and emails inside quoted text are masked or withheld. a publish that carries any of these is refused by a check on the built site.

what's not here

record bodies. the database points at them, it doesn't carry them. ip addresses of people, and handles of humans active before the incidents, are masked. encoded payloads are described by shape, not decoded.
